Three Firewalls

cha-audit-firewall-rule-analyzer analyses firewall rules from iptables, firewalld, or Windows Firewall to identify overly permissive or redundant rules, and it can audit a YAML or JSON configuration against a baseline.

iptables: rules are read from the Linux packet filtering framework of that name.

firewalld: rules are read from the dynamic firewall manager of that name.

Windows Firewall: rules are read from the Windows platform firewall of that name.

Two kinds of finding are named. A permissive rule is, by the word itself, a rule that allows more than it needs to. A redundant rule is, by the word itself, a rule that repeats what another rule already does. The source offers no examples of either, and no rule sample is printed on this sheet, since the source provides none.

One Command Line

python3 main.py -t TYPE [-c CONFIG] [-o OUTPUT]

The type choice is required. The config path is optional and bracketed. The output path is optional and bracketed. The bracketing in the original line is preserved and read as optionality, not redesigned.

Type Is Required

The one part of the command line that cannot be left out is the type: -t, also written --type, chooses which firewall is analysed, and the run has no default to fall back on.

Four Parameters

-hShows a help message and exits.
-t, --typeGives the type of firewall to analyse, required, with the three accepted values iptables, firewalld, and windows. This entry alone carries the ultramarine stroke at its left.
-c, --configGives the path to a configuration file in YAML or JSON.
-o, --outputGives the path to the output file for the report.

What Was Actually Run

Without -c, the tool runs the live firewall command for the chosen type: iptables-save for iptables, firewall-cmd --list-all for firewalld, and netsh advfirewall show allprofiles for Windows.

Live Run Not Performed in This Wave

That live step was not run in this wave because those commands are not available in the documenting environment. A live run was not possible there because the jsonpath_ng package is not installed and installs were not permitted in that wave. The parameter list comes from the argument parser in main.py, and the file compiles cleanly. These cautions are kept at full size, since a reader deciding whether to trust the parameter list deserves to know where it came from.
